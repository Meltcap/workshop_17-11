# Migrating AI from Gemini to LiteLLM

## Goal

Switch AI provider from Gemini to LiteLLM (OpenAI-compatible) for browser-only calls.

## Assumptions

- Endpoint is OpenAI-compatible at `https://llmproxy.fd.nl/v1/chat/completions`.
- Direct browser calls are allowed (CORS enabled for Authorization header).
- Model: `Azure/gpt-5-mini`.

## Files to Change

- `script.js`: constants; request body/headers; response parsing; error mapping; optional key test.
- `README.md`: config instructions for LiteLLM; remove Gemini references.
- `IMPLEMENTATION.md`: note provider switch and rationale.

## Implementation Steps

### 1) Replace AI constants in `script.js`

- Remove `GEMINI_API_KEY` and `GEMINI_BASE_URL`.
- Add:
  - `const LITELLM_API_KEY = 'YOUR_LITELLM_KEY_HERE';`
  - `const LITELLM_BASE_URL = 'https://llmproxy.fd.nl/v1';`
  - `const LITELLM_MODEL = 'Azure/gpt-5-mini';`
  - `const LITELLM_PATH = '/chat/completions';` (change to `/v1/chat/completions` only if base has no `/v1`)

### 2) Update `generateAdvice()` to call LiteLLM

- Build the prompt exactly as nu (kort NL, met disclaimer in system message).
- POST to `${LITELLM_BASE_URL}${LITELLM_PATH}` with headers:
  - `Authorization: Bearer ${LITELLM_API_KEY}`
  - `Content-Type: application/json`
- Body (non-streaming):
```json
{
  "model": "Azure/gpt-5-mini",
  "messages": [
    {"role": "system", "content": "Je bent een educatieve assistent... geen financieel advies."},
    {"role": "user", "content": "<hier de bestaande prompt>"}
  ],
  "temperature": 0.7,
  "max_tokens": 500,
  "top_p": 0.9,
  "stream": false
}
```

- Parse response text from `data.choices[0].message.content`.
- Keep existing 10s timeout handling.

### 3) Error handling in `script.js`

- Map statuses:
  - 401 → "LiteLLM API-sleutel is ongeldig"
  - 403 → "Geen toegang tot LiteLLM endpoint"
  - 429 → "Te veel verzoeken, wacht even"
  - 5xx → "AI-service tijdelijk niet beschikbaar"
- On non-OK, log full `error` body for debugging.

### 4) Optional: health check

- Add `testLiteLLMKey()` called in `initApp()` (after Finnhub check):
  - Send a tiny request with `messages: [{role:'user', content:'ok'}]` and verify `200`.
  - Show a notice if it fails with common hints (key, CORS, base URL).

### 5) Documentation updates

- `README.md`:
  - Replace Gemini setup with LiteLLM config table: `LITELLM_API_KEY`, `LITELLM_BASE_URL`, `LITELLM_MODEL`.
  - Mention OpenAI-compatible endpoint and CORS requirement.
- `IMPLEMENTATION.md`:
  - Add short section explaining the switch and request shape.

## Key Snippets

### Fetch call (JS)

```javascript
const url = `${LITELLM_BASE_URL}${LITELLM_PATH}`;
const body = {
  model: LITELLM_MODEL,
  messages: [
    { role: 'system', content: 'Je bent een educatieve assistent. Geen financieel advies.' },
    { role: 'user', content: prompt }
  ],
  temperature: 0.7,
  max_tokens: 500,
  top_p: 0.9,
  stream: false
};
const response = await fetch(url, {
  method: 'POST',
  headers: {
    'Authorization': `Bearer ${LITELLM_API_KEY}`,
    'Content-Type': 'application/json'
  },
  body: JSON.stringify(body),
  signal: controller.signal
});
const data = await response.json();
const adviceText = data.choices?.[0]?.message?.content?.trim();
```
